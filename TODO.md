What needs work for a public release (this was generated by Sonnet 4.7):

  1. The README still says YOUR_USERNAME in the clone URL. Needs a real GitHub org/repo. Small but signals "not
  ready."
  2. The 66 skipped tests — are those gated on optional deps, or actually broken? For a release, you want CI
  running them in matrix (one job with [dev], one with [dev,redact,embeddings]). Users will install extras and
  expect them to work.
  3. No CI at all — no GitHub Actions workflow. For a public PyPI package you need at minimum: lint (ruff), test
  matrix (py3.10-3.13), and ideally a publish-on-tag workflow.
  4. No CHANGELOG — you'll want one before 0.1.0 hits PyPI. Doesn't need to be fancy; a simple ## 0.1.0 -
  2026-05-XX with the feature list.
  5. docs/ references might be broken — the README links to docs/schema.md, docs/adapter-guide.md,
  docs/redaction.md. These exist, but I didn't verify they're up-to-date with the current schema (3 migrations in).
  6. ChatGPT adapter — the README and CONTRIBUTING both mention ChatGPT exports, but there's no adapter for it yet.
   Either build one or reword the docs to not promise it. For a launch, having ChatGPT + Claude is a strong one-two
   punch that widens the audience.
  7. The query CLI command has no SQL injection guardrails — unlike the MCP server which goes through
  execute_safe(), the CLI query command runs raw SQL against a read-write connection. Fine for personal use, but
  for a public tool someone might pipe untrusted input into it.
  8. _load_vss_extension silently tries INSTALL vss — this makes a network call (downloads extension from DuckDB).
  A public release should either document this or make it opt-in, since your README promises "no network calls."
  9. PyPI name availability — have you checked pip install chatstrata / pypi.org/project/chatstrata? Worth
  squatting the name now if it's free.
  10. A chatgpt_export or cursor adapter would meaningfully broaden the audience beyond Claude-ecosystem users.
  11. Add a compaction audit feature for Claude Code and Codex CLI transcripts. Detect compaction markers
  (`compact_boundary`, summary events, Codex `compacted` / `replacement_history`), preserve them as queryable
  metadata or a dedicated view, and report whether compaction was UI-only, source-transcript lossy, normalization
  lossy, or followed by suspicious behavior such as repeated discovery, contradicted decisions, missing constraints,
  or degraded tool success. A v1 could expose per-session checks for raw history preserved, normalized history
  preserved, compact summary present, skipped event types near compaction, and post-compact issue signals.
